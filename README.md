## Safety by design

```text
Student action / staff report
             ↓
Authorised verification and context review
             ↓
Configured responder queue and institutional procedure
             ↓
Policy-based guardian communication
             ↓
Restricted outcome record and audit trail
```

The SOS flow in this prototype uses a **three-second hold-to-send interaction** to reduce accidental taps. It is a visual product demonstration only: it does not contact emergency services, transmit a location, or notify a real person.

## Important scope

UniSathi is a **product-design and WordPress website prototype**, not a deployed emergency, surveillance or student-record system. All names, locations, attendance, alerts, timings and metrics are illustrative. A real implementation requires institutional policy, informed consent, role-based access, security review, staff response procedures and applicable legal/privacy assessment.

Reports involving bullying, ragging, wellbeing, medical support or suspected behaviour must be reviewed by authorised people. They should not automatically become unverified guardian allegations.

## Run locally

Open `index.html` in a browser to view the interactive experience. The WordPress theme source is in `unisathi/`; package it as a ZIP and upload it through **WordPress → Appearance → Themes → Add New → Upload Theme**.

## Publish with GitHub Pages

1. Open repository **Settings → Pages**.
2. Select **Deploy from a branch**.
3. Set branch to `main` and folder to `/(root)`.
4. Save. GitHub will publish the interactive static experience at the link above.
